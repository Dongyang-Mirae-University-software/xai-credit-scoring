## 1. 문제 정의 (1쪽)

- 씬파일러: 「금융 이력이 부족하여 기존 CB(신용평가) 모델로는 적절한 신용평가가 어려운 개인. 사회초년생, 프리랜서, 주부 등」
- 목표: 금융 데이터에 대안 데이터(통신비·공과금 납부 등)를 더해 씬파일러를 더 잘 평가하고, 결과를 설명(SHAP)하며, 차별 여부를 검증(공정성)한다
- 성공 기준 (원본): Test AUC 0.78 이상, KS 0.28 이상, 씬파일러 AUC uplift +0.03 이상, PSI 0.1 미만, DI Ratio 0.8 이상(1.25 이하), Equalized Odds 차이 0.10 이하
- 배경: 금융위원회 금융분야 AI 가이드라인의 설명가능성·공정성, 대출 거절 사유 고지 의무
- ✍️ 쓸 것: 왜 대안신용평가가 필요한지 한 문단, 시스템 한 장 그림

## 2. 데이터와 EDA (3쪽)

- 데이터: Kaggle Give Me Some Credit, 150,000명, 정답 `SeriousDlqin2yrs`(2년 안에 90일 이상 연체)
- 연체자 10,026명 (6.68%) → 불균형 데이터
- 결측: `MonthlyIncome` 29,731명, `NumberOfDependents` 3,924명 → 중앙값으로 채움
- 이상값: `RevolvingUtilizationOfUnsecuredLines` 최대 5만 이상, `DebtRatio` 최대 32만 이상 (#29 보정)
- 이 데이터의 특징: 금융 기록이 있는 사람들이라 진짜 씬파일러는 거의 없음 → 4장에서 대신할 기준을 정한 이유
- 🟡 쓸 것: 변수별 분포 그림, 연체 여부별 비교 표, 상관 행렬 그림 (EDA 노트북에서)

## 3. 대안 데이터 시뮬레이터 (2쪽)

- 원본: 「생성된 대안 변수와 Target 변수 간 상관계수가 0.3 \~ 0.5 범위 내」, 방법 1(공분산 행렬) 사용
- 5개 변수와 범위: 통신비 정상납부율(0-1), 공과금 납부율(0-1), 소비 일관성(0-100), 정기결제 건수(0-20), 앱 로그인 빈도(0-30)
- 팀 결정 A안 (#36): 원본 예시 코드 `np.clip(0.85 - 0.2 * target + noise, 0, 1)`처럼 **연체자일수록 낮게**, 상관계수는 크기(절댓값) 0.3-0.5
- 실행 결과 표 (`df.corr()`): 바꾸기 전 +0.32 - +0.49 → 바꾼 뒤 -0.32 - -0.49 ⏳ 최종 값으로 교체
- 납부율 수준 현실화: 정상 상환자 평균 약 0.9 (원본 거절 사유 예시 「평균(92%)」)
- 손잡이 두 개: `thin_filer_ratio`(기본 None = 기준대로), `bias_ratio`(기본 0, 공정성 실험에서만 사용)
- 한계 (11장과 연결): 연체율 6.7%에서 상관 0.4 변수는 하나만으로 AUC 약 0.9 → 통합 AUC가 매우 높게 나올 수 있음

## 4. 씬파일러 판정 기준 (1.5쪽)

- 원본 정의: 「금융 연체 관련 컬럼 2개 이상 결측치이거나 신용카드 거래 이력 12개월 미만인 고객」
- 이 데이터에서는 0명 (연체 칸에 결측이 없고, 카드 사용 기간 칸이 없음) → 대신할 기준을 팀이 정함 (#15)
- 팀 기준: 보유 대출·신용 한도 1개 이하 + 부동산 담보대출 0 + 연체 기록 0 → **4,110명** (연체율 7.2%, 35세 미만 38.7%, 전체는 13%)
- 근거
  - 업계: Experian은 활성 계좌가 5개 미만(일부 1-2개)이면 씬파일러로 봄
  - 데이터: 연체 기록·담보대출이 없는 사람의 연체율이 계좌 0개 13.0%, 1개 5.3%, 2개부터 2-3%로 평평
- 표현: "원본 정의를 이 데이터에 맞게 **대신했다**" (같다고 쓰지 않음)
- 초기 버전 문제와 수정: 30%를 무작위로 채워 씬파일러의 86%가 일반인이던 문제 → 기준만 쓰도록 수정 (#16)

## 5. 전처리와 분할 (1쪽)

- 결측 중앙값 채우기, StandardScaler, One-Hot 코드(글자 칸 없음)
- 70:15:15, `stratify=y` → 105,000 / 22,500 / 22,500명, 세 묶음 연체율 동일
- Validation으로 모델 선택, Test는 마지막 1회만 (#25) · 원본 「테스트 데이터의 라벨을 학습에 사용하는 것을 금지한다.」
- 분할 파일에 성별·연령대·씬파일러 표시·고객 번호 유지, 모델 입력에서는 제외 (#33)

## 6. 모델 학습과 비교 (3쪽) ⏳

- 9가지 조합: 데이터(금융만 / 대안만 / 통합) × 알고리즘(LR / XGBoost / LightGBM), 불균형 처리(class_weight·scale_pos_weight / SMOTE)
- MLflow: 실험별 params, metrics(AUC, KS, F1), artifacts(모델 파일), 최종 모델 Registry Staging (#32)
- 표: 조합별 Validation AUC·KS·F1, 최종 모델 Test AUC·KS·PSI ⏳
- 배운 점 (기록용): 10/8·10/9 기록은 옛 설정(bias 0.1)으로 학습돼 금융 데이터 LightGBM AUC가 0.69까지 떨어졌음 (깨끗한 데이터 0.865) → 편향 손잡이를 기본 0으로 바꾼 이유
- 씬파일러 AUC uplift: 대안 포함 모델 vs 미포함 모델을 씬파일러 집단에서 비교 (#27, 교차검증 예측으로 계산 권장) ⏳

## 7. XAI 분석 (3쪽) 🟡 ⏳

- SHAP TreeExplainer, Summary Plot(상위 15개), Dependence Plot 2개, Waterfall Plot (#38, PR #40, `main_step3.py`)
- 지금 옛 데이터 기준 성능(참고): XGBoost AUC 0.769 · KS 0.427, LightGBM AUC 0.771 · KS 0.431 ⏳
- 거절 사유 Top 5 예시: 「통신비 정상납부율이 78%로, 동일 연령대 평균(92%) 대비 낮습니다」 형식, 연령대 평균은 원본 3구간 기준
- 방향 결정 전후 비교 (발표용으로 좋음): 바꾸기 전 Summary에서 "공과금 납부율이 높을수록 위험"으로 나옴 → A안 이후 "낮을수록 위험" ⏳

## 8. 공정성 검증과 Bias Mitigation (3쪽) 🟡 ⏳

- 보호 속성: 성별(male/female), 연령대(20-34 / 35-54 / 55+)
- 지표: DI Ratio(보호 집단 승인율 ÷ 비보호 집단 승인율, 0.8 미만·1.25 초과 경고), Equalized Odds(TPR 차이, FPR 차이 0.10 이하) (#39)
- 기본 데이터(bias 0) 결과: 성별 DI 0.988, 연령대 DI 1.098, EO 모두 통과 ⏳
- 편향 실험: bias 0 / 0.1 / 0.2에서 집단별 승인율 변화 (#41에서 성별 대리 변수 추가 후)
  - 기록할 발견: 정답만 바꾸는 방식은 성별 승인율에 전달되지 않음 (성별이 입력이 아니고 대리 변수 없음), 연령대는 0.2부터 전달
- Mitigation 전/후 비교 표 (원본 필수): Threshold Adjustment, Reweighting ⏳
- 「공정성 분석 결과를 문서화하고 편향 완화 조치를 기록해야 한다.」 → 이 장 + 부록 결정 기록

## 9. ANOVA 통계 검증 (2쪽, 해석 1쪽 이상) 🟡 ⏳

- 검증 1: 피처 그룹별 (금융만 / 대안만 / 통합) One-way ANOVA (#42, PR #43, `main_step5.py`가 해석 문장까지 생성)
- 검증 2: 알고리즘별 (LR / XGB / LGBM) One-way ANOVA
- F, p, η²(0.01 / 0.06 / 0.14 기준), p < 0.05면 Tukey HSD
- 지금 기록으로 돌려 본 예 (옛 설정, 참고): 검증 1 F 145.35, η² 0.770 / 검증 2 F 23.62, η² 0.636, XGB vs LGBM 차이 없음 (p_adj 0.96) ⏳
- 해석 문단 (원본 예시 형식): "통합 모델(M=...)이 금융 모델(M=...)보다 유의하게 높은 AUC를 보였다(p_adj=...)..."
- 한계: 폴드 점수는 같은 데이터를 나눈 값이라 완전히 독립이 아님
